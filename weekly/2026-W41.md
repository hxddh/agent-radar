## English

### 1. Executive Summary

- This week's biggest change: OpenAI's Dots launch (persistent/always-on assistants) concretizes a new class of long‑lived agent artifacts (snapshots, scheduled-output archives, export hooks) and forces operators to treat agent state as first-class forensic/storage telemetry.
- Most important user experience signal: multiple operator incidents (credential leakage to shared channels; MCP connector regressions; DNS‑egress anecdote) show that agent outputs and connector fragility are active, exploitable failure modes.
- Most important infra signal: platform vendors are shipping first‑party runtime and MCP server implementations (modelcontextprotocol servers, MCP routers, Bedrock-hosted Agent Mode patterns) increasing both adoption and fragmentation risk.
- Most important storage implication: persistent assistants and large-scale Bedrock fleets require tiered, indexable snapshot retention and per-agent quotaing to avoid runaway object-storage bills.
- Biggest uncertainty: pricing/packaging for long‑running/background agents (seat vs task vs compute time) remains unresolved; evidence is fragmented.

### 2. Product Changes

- OpenAI — Dots (persistent assistants) published product materials describing scheduled tasks, long‑window state, and export/backup hooks. Operators must map Dots export manifests into retention and chain‑of‑custody playbooks. Source: https://openai.com/index/introducing-dots/ (Strong)
- Anthropic — Claude Code v2.1.296 release. Runtime/conductor deltas can change tool-call semantics and containment behaviors; prior community reports connect runtime upgrades to MCP connector regressions. Source: https://github.com/anthropics/claude-code/releases/tag/v2.1.296 (Strong)
- Cursor — added remote-control for local agents and a Security Reviewer to gate rollouts. This is a vendor-side rollout gate operators can integrate into CI. Source: https://cursor.com/changelog/remote-control-local-agents (Strong)
- AWS / Postman — documented production Bedrock Agent Mode scaling patterns (40M developers). Operational lessons for telemetry/retention at scale. Source: https://aws.amazon.com/blogs/machine-learning/how-postman-runs-agent-mode-for-40-million-developers-on-amazon-bedrock/ (Strong)
- Vercel agent-browser release updates (v0.39.0) and sandbox-memory/observability deltas encourage mapping preview/export sinks to short‑TTL storage. Source: https://github.com/vercel-labs/agent-browser/releases/tag/v0.39.0 (Strong)

### 3. Mainstream Agent Progress

- Persistent/always‑on assistants moved from concept to product (OpenAI Dots): adds new artifact classes and retention obligations. Evidence: vendor product page + HN discussion spike (Strong + Medium-Strong social).
- Bedrock-hosted agent fleets (Postman on Bedrock) provide a template for large multi-tenant managed agent hosting; scale lessons (per-agent snapshots, indexing) are operationally relevant (Strong).
- Vendor tooling is adding operator gates (Cursor Security Reviewer; Microsoft Foundry routines with egress controls) that materially change how operators can enforce safe rollouts (Strong).

### 4. Emerging Agent Progress

- MCP server ecosystem expanded: modelcontextprotocol servers, mcp-ai-router, and vendor MCP gateways surfaced this week (Medium). Multiple implementations increase choice but risk fragmentation without governance.
- Memory primitives & syncs: mem0/remem/agenticow variants remain active; no single dominant approach yet (Medium).

### 5. User Experience

- Concrete incidents this week underline real UX risk:
  - Personal AI assistant leaked bank details into a company Slack channel (Business Insider). Action: output filters, webhook/channel-level export controls, and PII detectors are required (Medium-Strong).
  - Community reports of MCP connector regressions after runtime upgrades (Reddit). Action: add connector contract tests in CI and require pre-upgrade snapshot+rollback runbooks (Medium).
  - Social report of DNS tunneling exfiltration during a training/eval run — emphasizes egress control gaps (Medium).

### 6. Useful Tricks

- Operational checklist (repeatable): snapshot active workspaces before runtime upgrades; add connector contract tests in CI; integrate vendor rollout gates (e.g., Cursor Security Reviewer) into preflight; enforce per-agent budget windows and circuit breakers (token / task quotas).

### 7. Infrastructure Changes

- Sandboxes & scaling: Modal/Daytona/others demonstrate extreme sandbox scaling and snapshot-as-search-state ideas; operator attention should be on network egress, ephemeral vs durable artifact classification, and snapshot indexability.
- Security advisories (Flowise GHSA) require immediate patching/fix or version pinning for affected sandbox runtimes — treat these as high-priority containment failures (Strong).

### 8. Storage Implications

- Persistent assistants + managed fleets => new artifact classes: agent-state snapshots, scheduled-output archives, export manifests. Operators must adopt tiered retention (hot <7d, mid 30–90d, archive 365d+) and per-agent quotas to bound costs.
- Bedrock-scale fleets (Postman example) require per-snapshot indexing and per-tenant cost allocation tags for S3-like stores; design snapshot manifests for efficient incremental retrieval and legal preservation hooks.

### 9. Commercialization

- Vendors are packaging runtime/operator controls (rollout gates, security reviewers) as product features — signals that agent governance is becoming a paid product differentiator. Pricing signals for long-running agents remain fragmented; no dominant pricing model emerged.

### 10. Enterprise Adoption

- Enterprise templates (Bedrock + Postman; Foundry routines) show managed-agent fleets in production; enterprises will demand export/forensics APIs and quotaing controls as contractual features.

### 11. Reliability and Evaluation

- Eval & observability vendors (Langfuse, agent-eval tools) continue incremental releases; operator telemetry must expand to cover agent-state drift, connector health, and export manifests.

### 12. Security and Governance

- Increased risk posture: vendor containment posts (Anthropic), OpenAI training/eval pauses, and multiple sandbox advisories this week raise short-term regulatory and operational risk.
- Governance levers: vendor rollout gates (Cursor), CI connector contract tests, egress network controls, and per-agent budget/circuit-breakers are immediate mitigations.

### 13. Ecosystem Standards

- MCP proliferation: multiple MCP servers and router projects surfaced (modelcontextprotocol servers, mcp-ai-router); increased adoption signals but no single default — convergence vs fragmentation remains an open governance question.

### 14. Anti-Signals

- Fragmented pricing signals and connector regressions are counter-evidence to a smooth, vendor‑led migration to cloud task runners; they favor conservative operator strategies (pinning, staging tests).

### 15. Changed Thesis

## 中文

### 1. Executive Summary

- 本周最大的变化：OpenAI 的 Dots 推出（persistent/always-on assistants）将持久化/长期存在的代理工件（快照、计划输出归档、导出挂钩）具象化，迫使运营方将代理状态视为一等的取证/存储遥测。
- 最重要的用户体验信号：多起运营事故（凭证泄漏到共享频道；MCP 连接器回归；DNS 出口通道的轶事）表明代理输出和连接器脆弱性是活跃且可被利用的失效模式。
- 最重要的基础设施信号：平台厂商正在交付第一方运行时和 MCP 服务器实现（modelcontextprotocol servers、MCP 路由器、Bedrock 托管的 Agent Mode 模式），这既增加采用也增加分裂风险。
- 最重要的存储含义：持久助理和大规模 Bedrock 舰队需要分层、可索引的快照保留策略与按代理配额，否则会导致对象存储账单失控。
- 最大的不确定性：对长期运行/后台代理的定价/打包（按席位、按任务还是按计算时间）仍悬而未决；现有证据呈碎片化。

### 2. Product Changes

- OpenAI — Dots (persistent assistants) 发布了描述计划任务、长窗口状态和导出/备份挂钩的产品资料。运营方必须将 Dots 导出清单映射到保留和链条持有(playbook)流程。Source: https://openai.com/index/introducing-dots/ (Strong)
- Anthropic — Claude Code v2.1.296 发布。运行时/指挥器差异可能改变工具调用语义和隔离行为；先前社区报告将运行时升级与 MCP 连接器回归联系起来。Source: https://github.com/anthropics/claude-code/releases/tag/v2.1.296 (Strong)
- Cursor — 为本地代理新增远程控制和 Security Reviewer 以门控上线。这是厂商端的上线门控，运营方可以将其集成到 CI 流程中。Source: https://cursor.com/changelog/remote-control-local-agents (Strong)
- AWS / Postman — 记录了生产级 Bedrock Agent Mode 的扩展模式（40M developers）。提供了大规模遥测/保留的运维教训。Source: https://aws.amazon.com/blogs/machine-learning/how-postman-runs-agent-mode-for-40-million-developers-on-amazon-bedrock/ (Strong)

### 3. Mainstream Agent Progress

### 4. Emerging Agent Progress

- 存储原语与同步：mem0/remem/agenticow 等变体仍在活跃；尚无单一主导方案（Medium）。

### 5. User Experience

### 7. Infrastructure Changes

- 沙箱与扩展：Modal/Daytona/其他展示了极端的沙箱扩展和将快照作为搜索状态的想法；运营者应关注网络出口、临时与持久工件的分类，以及快照的可索引性。
- 安全公告（Flowise GHSA）要求对受影响的沙箱运行时立即打补丁/修复或进行版本固定——将这些视为高优先级的遏制失败（Strong）。

### 8. Storage Implications

- 持久助理 + 托管舰队 => 新的工件类别：代理状态快照、计划输出归档、导出清单。运营方必须采用分层保留（hot <7d, mid 30–90d, archive 365d+）并对每个代理设置配额以界定成本。
- Bedrock 规模的舰队（Postman 示例）需要对每个快照建立索引并为租户分配成本标签以适用于 S3 类存储；设计快照清单以实现高效增量检索和法律保存挂钩。

### 9. Commercialization

- 厂商正在把运行时/运营者控制（上线门控、安全审查器）打包为产品特性——这表明代理治理正在成为付费产品的差异化点。长期运行代理的定价信号仍然分散；尚无主导定价模型出现。

### 10. Enterprise Adoption

- 企业模板（Bedrock + Postman；Foundry 例程）显示托管代理舰队已在生产环境；企业将把导出/取证 API 和配额控制作为合同特性要求。

### 11. Reliability and Evaluation

- 评估与可观测性厂商（Langfuse、agent-eval 工具）持续发布增量更新；运营方的遥测必须扩展以覆盖代理状态漂移、连接器健康和导出清单。

### 12. Security and Governance

- 风险姿态提升：厂商隔离公告（Anthropic）、OpenAI 的训练/评估暂停以及本周多起沙箱公告提升了短期的监管与运维风险。
- 治理杠杆：厂商上线门控（Cursor）、CI 连接器契约测试、出口网络控制和按代理预算/断路器是立即可用的缓解措施。

### 13. Ecosystem Standards

- MCP 的扩散：本周出现了多个 MCP 服务器和路由项目（modelcontextprotocol servers、mcp-ai-router）；采用增加但尚无单一默认——收敛与分裂仍是开放的治理问题。

### 14. Anti-Signals

- 碎片化的定价信号和连接器回归是对由厂商主导的平稳迁移到云任务运行器的反面证据；它们支持保守的运营策略（版本固定、分阶段测试）。
