### 4. Playbook Promotions

Promote the following playbook candidates to operator‑level checks/actions:

- Pre‑upgrade snapshot & smoke tests: require workspace snapshots and end‑to‑end connector smoke tests staged to a pinned runtime before any runtime/SDK upgrade.
- Publish token scoping & pre‑publish CI gates: enforce least‑privilege publish tokens for agent‑driven package publishing; add publish dry‑run and artifact signature checks in CI.
- CASB mapping for agent artifact types: map agent telemetry, transcripts, audio blobs, and diagnostic exports to CASB detection/remediation policies and test auto‑remediation workflows in staging.
- MCP connector exposure hardening: default connectors to authenticated, egress‑filtered endpoints; document any operator recipes that expose MCP endpoints (follow up with lab reproduction of the Bluesky how‑to).

### 5. Storage and Infrastructure Thesis

### 6. Commercialization and Enterprise Adoption

### 1. Executive Summary

- 最强的产品信号：Vercel ai@7.0.101 发布和 Cloudflare agents@0.23.0（语音/诊断）——平台厂商继续将 agent 运行时和入门流程产品化。

### 4. Playbook Promotions

- 预升级快照与冒烟测试：在任何运行时/SDK 升级前，要求工作区快照并将端到端连接器冒烟测试在固定运行时上演练。
- 发布令牌作用域与预发布 CI 门禁：对 agent 驱动的包发布强制最小权限的发布令牌；在 CI 中增加发布演练（dry‑run）和工件签名检查。
- 将 agent 工件映射到 CASB：将 agent 遥测、转录、本地语音二进制和诊断导出映射到 CASB 检测/修复策略，并在预生产环境测试自动修复工作流。
- MCP 连接器暴露加固：默认将连接器设置为需认证且有外发过滤的端点；对任何公开 MCP 端点的运营者做法编写文档（并在实验室复现 Bluesky 教程中描述的情形）。

### 5. Storage and Infrastructure Thesis

- 运营者必须将 agent 工件视为一等对象存储租户：音频转录、诊断归档、会话快照和多模态嵌入会将容量和保留需求纳入 S3/R2/GCS 的规划范围。
- 可执行的差异：为不同工件类型增加存储分层；为每类工件设定 TTL/保留策略；为多模态 KB（AWS Bedrock）和 Astra 快照格式（OpenAI notes）规划增加的外发与索引成本。

### 6. Commercialization and Enterprise Adoption

- 平台厂商（Vercel、Cloudflare、Modal）继续将托管沙箱与入门流程产品化——这降低了运营摩擦，但也将工件保留与遥测集中在厂商默认设置之下。企业采购必须包括工件保留/外发 SLA 与审计访问条款。

### 7. Security and Governance

- 供应链风险升高：agent 驱动的包发布导致了恶意 RubyGems（媒体调查）。运营者的紧急缓解措施：限制发布令牌、要求包签名，并在预发布加入静态检查。（证据：Reuters；The Guardian）
- 平台遏制原语在改进（Cloudflare CASB、Daybreak、写保护），但关于每种工件类型的覆盖文档不完整。运营者应将平台规则与实际工件流进行核验。

### 8. Open Questions Resolved

- Platform‑vendor momentum：部分得到解决——厂商发布与托管沙箱确认了平台参与度在加速（对 Thesis 8 的置信度提高），但厂商默认设置也为运营者带来新的保留/外发责任。

### 9. Open Questions Added

- 厂商的 SOC/取证产品能否跟上新工件类型（语音、多模态嵌入）的节奏，还是运营者需要构建定制化的取证管道？
- 可重复的预发布与连接器加固模式能否在不同 MCP 实现之间标准化，以降低供应链风险？
